Section 01

Revised product architecture

A single, consistent configuration model across the catalogue — so every product page feels like the same calm, premium showroom assistant, regardless of category.

The configuration model

Each product is assembled from a predictable stack, revealed through progressive disclosure — show the essential choice first, reveal complexity only when the customer asks for it.

  1. Primary variant — the one decision that changes everything (size for rugs & cushions; size/configuration for furniture). Always visible.
  2. Material & finish — swatches with names and macro imagery; selecting updates the gallery and price.
  3. Refinements — backing, fill, upholstery grade — shown contextually, with a one-line "what this means".
  4. Decision support — size guide, sample request, WhatsApp consultant — adjacent to the choice they support.
  5. Customization escape hatch — "Need a custom size or finish?" → WhatsApp, for anything the variant matrix can't express.

Principle — never overwhelm

If a product has many options, group them, label them in plain language, and default to the most popular configuration. A buyer should be able to add to cart in one decision, or go deeper if they want to. Price and lead time update live with every choice.

Live feedback on every change

  • Price updates instantly per variant (cover-only vs cover + filler, size, top material).
  • Gallery swaps to the selected finish/colour where imagery exists.
  • Lead time / availability reflects the variant ("In stock" vs "Made to order · 3–4 weeks").
  • Sample & WhatsApp CTAs carry the selected configuration into their pre-fill.

Section 03

Buying decision framework

Every high-ticket purchase clears five kinds of doubt. The PDP should answer each, in this order, before the customer has to ask.

ConfidenceWhat the customer needsOn-page solution
Visual"What does it really look like, at scale, in a room?"Lifestyle-first gallery, craftsmanship macros, scale/in-room reference shot, finish-accurate imagery.
Material"What is it made of, and will it last?"Materials block + construction notes + care; Wood/Finish/Upholstery guides; Request Sample.
Size"Will it fit my space?"Dimension diagram, room-placement visual, size-comparison graphic; Rug Size Guide; "Will it fit?" note.
Trust"Can I rely on the brand & delivery?"Delivery timeline, assembly & delivery info, handcrafted process, warranty, returns — near the buy box.
Purchase"What if I'm still unsure?"WhatsApp consultant, sample, customization, consultation booking.

The rule

If a buyer would have to message you to ask it, the page should already answer it — or offer the one-tap WhatsApp path. Every answered question is a recovered conversion and a support request avoided.

Section 05 & 06

Missing trust signals & conversion features

Missing trust signals

  • Delivery estimator & per-variant lead-time visibility.
  • Warranty & returns clarity on PDP.
  • Handcrafted process explainer per product (not just homepage).
  • Material transparency — origin, construction, care.
  • Scale/room reference imagery as standard.
  • Customer Homes / designer credits as social proof.

Missing conversion features

  • Sticky Add to Cart + WhatsApp (desktop & mobile).
  • Request Material Sample (furniture & upholstery).
  • Rug Size / Placement / Material guides.
  • Finish / Wood / Upholstery guides (furniture).
  • Cushion size guide + styling combinations.
  • Cross-sell: Frequently Styled Together · Complete the Room · Designer Recommendations.
  • Shop by Room / Style / Material / Size on collections.
  • Recently viewed · save for later.

Cross-sell, the luxury way

"Complete the Room" and "Frequently Styled Together" should read as a stylist's suggestion, not an upsell — italic serif captions, real room imagery, 3–4 considered pieces. This is the primary AOV lever.

Section 07

Shopify · Prestige implementation roadmap

Maximise native Prestige; minimise custom code. Variants handle configuration; metafields carry the storytelling and decision-support content.

Variant architecture

  • Model real, purchasable choices as variants (size, finish, material, backing, fill) — so price, image, inventory & lead time are native.
  • Keep within Shopify's option limits; where a category needs many finishes, use a finish swatch metafield driving variant images rather than exploding the matrix.
  • "Custom size/finish" is not a variant — it's a WhatsApp/enquiry CTA.

Template & UX changes

  • Product: sticky buy bar (Add to Cart + WhatsApp + Sample), live-updating variant blocks, metafield-driven Materials/Dimensions/Care, guide launchers (drawer snippets).
  • Collection: Shop-by-{Room/Style/Material/Size} tile rows, quick-view, merchandising blocks via Prestige sections.
  • Mobile: sticky Add-to-Cart + WhatsApp; bottom-sheet variant pickers & guides; large swatches; bottom-sheet filters.
  • Performance: native responsive images, lazy-load, reserved aspect ratios; guides as lightweight snippets; minimal JS; respect reduced-motion.
Tagging
Use product type / tags (rug, furniture, upholstery, cushion) to conditionally render the right CTAs & guides.
Maintainability
Merchandisers edit metafields & collections — no code. Custom Liquid limited to the buy-bar, guide drawers & WhatsApp link builder.
